# MSGI Mining subtask graph: source and license

**Citation.** Sungryull Sohn, Hyunjae Woo, Jongwook Choi, Honglak Lee. Meta
Reinforcement Learning with Autonomous Inference of Subtask Dependencies.
ICLR 2020. arXiv:2001.00248. The Mining domain and the subtask-graph format
come from Sohn, Oh and Lee, Hierarchical Reinforcement Learning for Zero-shot
Generalization with Subtask Dependencies (NeurIPS 2018). Mining is the
authors' own simplified design inspired by Minecraft (26 subtasks over 13
objects, defined in `mining.py`), not a copy of Minecraft's recipe tables.

**Source.** https://github.com/srsohn/msgi at commit
`e665861f2d08f41b7dad16588447203e5010145a` (default branch `master`,
retrieved 2026-10-08): `grid-world/environment/data/task_graph_mining/full_mining.pkl`
(the subtask graphs) and `grid-world/environment/mining.py` (subtask names,
operations and objects).

## Extraction

The pickles are `torch.save` lists of dicts (`ANDmat`, `ORmat`, `rmag`,
`trind`, `W_a`, `W_o`). `extract.py` loads them with
`torch.load(weights_only=True)` and an explicit allowlist of the NumPy
reconstruction functions they reference, so no other code in a pickle can
run. Each subtask's precondition is an OR over AND-nodes. The file holds 222
graphs; every one is a subgraph of a single rule set over the 26 Mining
subtasks (checked for every subtask of every graph), which is what
`mining_graph.json` stores, together with each subtask's operation (`pickup`
or `transform`) and object. The task files (`train1_*`, `eval1_*`, 200 and
440 graphs) use the same rules for the subtasks they contain. No graph has a
negated precondition.

## What the loader reads

`loaders.load_msgi_mining`: subtasks without preconditions (`Cut wood`,
`Get stone`, `Get string`) are base facts. Every other subtask has one recipe
per AND-node, which requires the node's subtasks plus the object the subtask
is executed at (`obj:furnace`, `obj:jeweler`, ...); in the source the object
requirement is implicit (the agent must reach the object), and here it is a
base fact. `Light furnace` has two recipes (firewood or coal), the only OR in
the domain. Rewards and the per-task subtask subsets are not part of the graph.
